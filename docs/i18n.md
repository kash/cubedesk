# Idiomas e internacionalización

CubeDesk admite inglés y español. El idioma se cambia en **Ajustes → Idioma y región**.

## Preferencia y renderizado

La preferencia se guarda en la cookie `cubedesk_locale` durante un año. Usa `SameSite=Lax` y `Secure` con HTTPS; no se guarda en la cuenta ni en la base de datos.

El servidor selecciona el idioma por este orden:

1. Una cookie válida.
2. El primer idioma de `Accept-Language`.
3. Inglés.

La lógica de selección está en [shared/i18n.ts](../shared/i18n.ts). [server/router.tsx](../server/router.tsx) crea un `I18nProvider` por renderizado SSR; el proveedor crea una instancia independiente de i18next, de modo que las peticiones no comparten idioma. El HTML incluye el idioma seleccionado en `lang`, que el cliente lee durante la hidratación para producir el mismo texto. El selector cambia el idioma de la instancia actual y actualiza la cookie.

## Catálogos y componentes

[client/i18n/index.tsx](../client/i18n/index.tsx) configura i18next y react-i18next. Los catálogos de `client/i18n/messages/en/` y `client/i18n/messages/es/` tienen los mismos dominios y claves. Se usan claves planas con puntos (`keySeparator: false`), por ejemplo `timer.options.inspection`.

Cada texto visible de todas las páginas debe tener una clave semántica en ambos idiomas: títulos, párrafos, estados, errores, avisos, menús, formularios, etiquetas accesibles y contenido legal. Las frases inglesas no son identificadores de traducción. Para traducir en un componente consumidor:

```tsx
const {t} = useTranslation();
return (
	<SelectField
		label={t('settings.language')}
		options={[{value: 'es', text: t('common.spanish')}]}
	/>
);
```

Los controles reutilizables como `Label`, `Input`, `Select`, `ActionMenu` y `DialogContent` muestran literalmente el texto recibido. El consumidor traduce etiquetas, opciones, valores predeterminados, mensajes y textos accesibles antes de pasarlos.

Para valores variables usa interpolación (`{name}`); para cantidades define variantes `_one` y `_other` y pasa `count`:

```ts
t('community.won', {name: winner.username});
t('community.players', {count: players.length});
```

Traduce frases completas con sus variables; evita unir fragmentos ingleses alrededor de un número o una fecha. Por ejemplo, un aviso de métricas usa `admin.metrics.importTrackingSummary` con `count` y `formattedCount`. No construyas claves a partir de frases ni elijas las formas plurales con un ternario. Las claves dinámicas deben proceder de un conjunto explícito de identificadores semánticos.

## Añadir otro idioma

Añade el código de idioma en `SUPPORTED_LOCALES` de `shared/i18n.ts`, crea un directorio con los mismos dominios y claves que `en/`, regístralo en `client/i18n/messages/index.ts` y añádelo al selector. Completa el catálogo antes de publicar; el fallback sigue siendo inglés.

Las páginas de privacidad y términos también están localizadas por completo, no solo sus títulos. Sus bloques de contenido usan claves estables `legal.privacy.blockNNN` y `legal.terms.blockNNN` en los catálogos `privacy-document.ts` y `terms-document.ts` de ambos idiomas. La estructura y los enlaces siguen en los componentes React. Conserva el identificador de un bloque cuando edites su texto; al modificar una cláusula, actualiza el bloque equivalente en los dos catálogos y revisa la traducción jurídica antes de publicar cambios contractuales.

## Comprobación

```sh
node scripts/check-i18n.cjs
node_modules/.bin/jest client/i18n/i18n.test.tsx --runInBand
node_modules/.bin/tsc --noEmit --pretty false
pnpm run build
```

El comprobador detecta claves ausentes, duplicadas o sin uso, plurales incompletos e interpolaciones distintas entre idiomas. `pnpm exec tsc` puede detenerse antes de iniciar TypeScript por un desajuste del lockfile; el ejecutable local permite verificar los tipos.

Comprueba además el cambio de idioma, la recarga, SSR e hidratación y los textos de formularios, ajustes, temporizador, menús y accesibilidad en ambos idiomas.
